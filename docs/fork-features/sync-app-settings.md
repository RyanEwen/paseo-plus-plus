# Sync app settings

Choose a settings host in Paseo++ on Android or desktop to share preferences across your clients, including whether Usage appears in the sidebar, chat display and the Enter or Ctrl/Cmd+Enter send shortcut. Switching hosts loads their saved settings first; an empty host requires an explicit publish action. Fonts, text sizes, content width, terminal scrollback, keyboard mode, link/pane placement, automatic explorer opening and platform-specific tab/layout/update toggles stay on each device. Connection details, project filters, workspace order and collapsed groups also stay local. Device preferences remain editable while the settings host is unavailable or read-only, after local preferences load. A save that mixes local and shared changes keeps its local changes if the host rejects the shared changes. Your settings host needs a daemon build with settings sync support. Older settings hosts show an update instruction for the new chat preferences; publishing to them omits those fields. Device-only use and local backups preserve both choices. Shared settings refresh when the connection’s write permission changes. Retry recovers failed initial reads without leaving editing disabled. Read-only connections can retry the read without restarting the app or replacing saved preferences.

[Feature branch](https://github.com/RyanEwen/paseo-plus-plus/tree/feat/app-settings-sync). The guide on `main` describes the integrated behavior.
