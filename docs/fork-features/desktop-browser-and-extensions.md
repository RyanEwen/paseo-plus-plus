# Desktop browser and extensions

Desktop browser tabs use resident DOM Electron webviews with the shared persistent browser profile. Pages stay attached across workspace changes. Menus use the normal DOM overlay plane; opening one no longer takes a still frame or hides the page. Device presets preserve page-CSS dimensions across independent page and app zoom. Use the page zoom menu to resize web content separately from the Paseo interface. Pages on the same origin share zoom according to Chromium’s policy.

Browser pages use the bundled Chromium version in their user agent, without the Paseo and Electron product labels. Chromium is the permanent default for tabs, native popups and other embedded pages, helping sites that reject embedded-browser labels load normally. Every main Paseo UI window explicitly keeps the app's original branded identity. In a private installed Windows VM candidate, tabs and native popups used this identity from their first requests, popups kept their opener, Microsoft Partner Center's public landing page loaded without an access denial, and initial and additional Paseo UI windows stayed branded. Sign-in, released builds, physical Windows hardware and other platforms remain unverified.

Manage Chrome extensions in **Settings → Browser → Extensions**, and open their popups from the browser toolbar. Pinned icons and the Extensions menu show the extension's own badge text and colors for the current page. Compatibility depends on Electron's APIs; installation does not guarantee every extension works. On Linux, use a non-root desktop session for extension background activity. Launches that disable Chromium's OS sandbox keep it disabled. Root launches retain their existing behavior; equivalent extension background activity under root remains unsupported by this correction and unqualified. Packaged Linux verification of this startup correction is still pending. Background storage notifications use a private listener so extension state can follow popup and page changes. Confirmed extension-host crashes trigger a limited automatic restart; repeated failures keep **Retry** available in Settings. A restart can lock a password manager or require retrying autofill; Windows inline UI can still crash. See [Browser](../../public-docs/browser.md#chrome-extensions) for recovery limits. Extensions are not updated automatically. Pin extensions from the Extensions menu to keep their icons in the browser toolbar. Pins are local to the desktop browser profile and shared across panes and windows. Disabling an extension hides its icon without forgetting the pin; uninstalling removes it. Toolbar buttons use the existing supported popup actions. See [Browser](../../public-docs/browser.md) for supported actions and limitations.
